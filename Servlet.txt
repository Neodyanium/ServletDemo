* Client and Server Architecture

- Any device/computer where we can use internet to access via browser to access some service then it is a client.
- The client is a user or system that is request a specific resource or service from an entity called as Server 

-Internet is a global communication system that links thousands of individual network. It allows the exchange of info between 2 or more computers on a network.

- A machine where you make your service available to people globally can be called as a Server
- A sever maybe responsible to process one request or more on request time

- Webserver is a software program or server computer which has a world wide web access 


- The interaction between the webserver and webbrowser is done with the http protocol
- When we want to access the service we need to provide the web browser the address(IP) of the machine and if the server has multiple applications we need to provide the port address, but all this things are handled by the DNS (domain name server, ig it is like a registry where they map server name to the server ip)



* Static and Dynamic Response

- Static response is when the output doesn;t change with User. (Html, CSS)

- Dynamic response is which will change with the user (Servlet, JSP, php etc)

consider an eg, You are filling a registration form so that is a static html/css page, whereas upon registration you receive, Your Name + Registration details that is a dynamic response

* Lifecycle of Servlet

- The webcontainer is responsible for running the servlet. Many methods comes when we implement HttpServlet and they are called internally.

- The Servlet class works like any other when it comes to class loading, so any static blocks will be executed, then
comes the class instantiation so a constructor will run, after this the init method is called internally(any initialisation tasks can be done under these blocks), init used for db connections or configs reading

-After this the service method is called when we receive a request, for each request a new thread is created and each
thread then runs the service method. Service creates a request and response object, service method is called by web
container, the default Service method directs/calls doPost() or doGet() depends on the request method type. When we
override it, it simply runs the service method.

eg: A login servlet could be mapped to /login.
    When the user first visits /login, the browser sends a GET request. HttpServlet.service() sees that it is a GET request and calls doGet(), which can display the login form.

    When the user submits the form, the browser sends a POST request to the same /login URL. service() sees that it is a POST request and calls doPost(), which can process the submitted username and password.

    *** So the same URL can have different behavior depending on the HTTP method, managed by service method.

- At the end, when shutting down Tomcat, container calls a destroy method is called which shuts down the servlet

- The init() and destroy() methods are only called once in a Lifecycle, only Service can be called multiple times

Qs, The responsibility to create a Servlet is of the Web Container or Servlet container (here it is Tomcat). It works
lazily, so instantiation of a servlet happens when a request is received and not when we start the server.

*****The PRG (Post/Redirect/Get) Pattern, Under this the doPost() and doGet() has simple responsibilities, doPost() receives and process data, add it to database or any other thing it does not render HTML. Instead, it ends by executing a redirect, to a view(get method). doGet() Its sole job is to fetch and display data It simply reads the current state and uses PrintWriter or a JSP file to display the final result, doesn't change any data. This is how multiple reload will have no effect, since at the end we are getting a view, a get request that doesn't change the data.

*** The response.sendRedirect() , return a view as it will discard current request data and work towards sending
Redirect, in here you pass the path of jsp. Thus, the syntax that must be used here is
response.sendRedirect(request.getContextPath() + "/filename.jsp");

* Other than this if we have more Servlets we can pass the request to another Servlet. We get the request dispatcher  object from request object and call any of the 2 methods
1) Forward: It forwards the request that came from client to another Servlet and the response is given by the Servlet where the request was forwarded to.
2) Include: Here is simply does its thing and the response of included servlet(second) is added with the response of the
 receiver Servlet(first Servlet/Dispatcher Servlet)

**Note: The forward will discard any of first servlet response, no view from it, response of second servlet is shared
with client. Include has both of the responses

* JSP (Java Server Pages) are extension of servlet are used when we want a dynamic response that is a user specific response. Since it is an extension of Servlet we can write all the html and all the Servlet logic in JSP


-we usually separate the operations, servlet are for receiving request, then another Servlet/class/method, should handle the business logic, or logical processing and view. 


-  "<%  %>"  is a scriptlet tag, we can use it to add code we can write in a service class, internally it will be converted to a servlet. We don't need to create a class or request object, they are created internally and are ready to use. They also provide a PrintWriter Object called "out" if we want to use it to write the response. 
eg:

<%
	
	out.println("<h1> Thanks for registering </h1>");
	Date date = new Date(); 
	String city = request.getParameter("city");

 %>
- if we want to create an instance variable or an instance method, then we use <%!  %>
eg:
<%! int age=18; %>

- We mostly have all the objects we need implicitly created by JSP, what if we need an object from another package, we can do imports in the following and use in scriptlet
 <%@ page import="java.util.Date,"java.util.HashMap"  %>

- Expression tag is used to use variable actual data, <%= %> , eg: 
<%=  date   %>
<h1> <%= city %> </h1>



*** Internally it will create a Servlet class which extends the HttpServlet and adds the code written in various tags, it will be slower. Practically, the views and Servlet should be separated

------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
Servlet vs JSP

1) Servlet has Java code, where as JSP is a tag based file, so everything is included between tags, you want to use java code in JSP using tags too.

2) JSP is little slower, if you write Servlet logic inside JSP, whereas Servlet directly compiles into Machine code and is executed by the Servlet container, JSP will be first made into Servlet behind the scenes

3) If you are using Servlet to write to reponse, if you change the servlet code when it is already deployed/running the changes won't be reflected you will need to re-run/redeploy the server to get the updates. This is not the case with JSP as request Handler, any change in JSP will be rendered on a reload.

** MVC design Pattern, Model-View-Controller pattern

-Controllers (a Servlet) handles the client requests, if it is requesting data it forwards the request to Model(JDBC), the Model returns data that is then given to the view to present to the client. 

-Model usually has JDBC handeling, it works according to the request, whether to fetch or add data and returns the output to controller.

-View provides html or jsp reponse back to the client. 

Here each of these components has an individual work of routing, DB operations and rendering a view, the Model and View should never interact with each other. Controller should be the one to enable the communication.

                            |       MODEL       |
                            |      (JDBC)       |

    │                         4. Forwards State         1. Dispatches Form
    │                            & Request Context         Parameters (POST)

    └───────────────────────────────────────────────────►
                         5. Sends Rendered UI Response

*** They are separated so the management of the individual component gets easy and loose coupling helps easy modifications. There could be steps involved between controller and Model/view, which is handled by controller.
